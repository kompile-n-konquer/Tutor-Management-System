# Sprint 3
**([start date — fill in] → [end date — fill in])**

*(Mirrors the Gitea Milestone for Sprint 3, used as the sprint's defined goal and scope. Milestone date: 28 Sep 2026.)*

## Goal

Deliver the MS3 testing and quality milestone alongside the stakeholder-driven usability work: full backend and frontend test suites with 90% coverage gates enforced in CI, the accessibility theme system and dark mode prompted by client feedback, the landing page redesign, and the excuse/volunteer tutor workflow.

## Scope — Implementation

- MS3 testing milestone (PR #53): full backend (16 suites / 291 tests) and frontend (34 files / 261 tests) suites, 90% coverage thresholds enforced in CI
- Timesheet workflow, allocation removal, route wiring, and excuse/volunteer lifecycle covered by new tests
- Coverage gaps reviewed as a team, identified and logged for follow-up
- Accessibility theme system (PR #65): light / dark / follow-system modes, high-contrast mode, and colour-vision-deficiency palettes — implemented in response to the 17 Aug client meeting
- Dark-mode toggle in the top nav (PR #70)
- Landing page redesign: hero, benefits, features, contact and footer sections rebuilt as a modular Home page
- Tutor excuse / volunteer feature (PR #48, issue #37): focused tutor dashboard with assigned courses, upcoming sessions, and "Excuse myself" action
- CI/CD: SonarQube analysis workflow and Ubuntu runner set up
- Personalised tutor dashboard greeting; custom 404 page
- Vercel deployment config finalised

## Sprint Review

### Ndumiso — MS3 Testing & Quality Gate

**The good:** We shipped the MS3 testing milestone on PR #53 with full backend and frontend suites (16 suites / 291 tests and 34 files / 261 tests respectively) and 90% coverage thresholds enforced in CI, so quality can no longer silently regress. Despite main moving twice during the sprint, we resolved all 8–10 conflicting files each time without losing either side's work, kept the branch continuously green, and the test effort paid off beyond coverage — it caught a real unhandled-rejection bug in the availability editor and surfaced stray debug logging. The PR closed the sprint mergeable, CI-green (backend, frontend, SonarQube), and with a clean L3 security review.

**The bad:** Coverage on main's new UI work (dashboard, profile) landed as debt — after the final merge, frontend branch coverage had fallen to 83.9% and needed a late, unplanned push of ~30 tests to recover the gate; ideally those tests would have been written against the feature PR (#48) before it merged, not after. Our frontend tests also proved brittle: main's copy and skeleton-loader changes broke 15+ tests at once, showing we over-assert on exact wording and DOM details rather than behaviour. Finally, long-lived branch-vs-main friction cost us repeated conflict-clearing sessions, and a few hygiene lapses (a debug `console.log` and junk root files) slipped through review and had to be cleaned up here — a reminder to keep PRs short-lived and review hygiene stricter.

### Nhlamulo

We could have done better to work a bit more together and spread the workload over the course of the sprint, but we got the work done, which is what I appreciate about my groupmates. They definitely don't skimp out in putting in the work.

## Coverage Review — Gaps Identified and Logged

`npm run test:coverage` was run on both sides. Backend (Jest, two-layer gate: per-module 90% + global ratchet floors) finished at 59.08% statements / 50.00% branches / 63.20% functions / 59.24% lines, with `controllers/timesheets.js` at 99.72% statements and `controllers/allocation.js` at 100% statements — both gate layers pass. Frontend (Vitest, 90% global thresholds) finished at 98.58% / 90.85% / 97.97% / 98.67% — all four metrics above the gate.

Logged follow-up gaps (priority order):

1. `controllers/applications.js`: 0% (327 lines)
2. `controllers/events.js`: 0% (392 lines)
3. `controllers/settings.js`: 0% (293 lines)
4. `controllers/courses.js`: 6.96% (most handlers unexercised)

Ratchet note: the next suite (applications, events, or settings) should raise the global floors in `backend/jest.config.js`, and `timesheets.js` is now a candidate for promotion from the ratchet bucket to the per-module 90% gate list.

It remains an open backlog item (assigned at the 13 Sep team meeting). When implemented, it must ship with its own suite. This is the one Intermediate-tier item MS3 leaves open on the testing side.
